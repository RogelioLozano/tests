# tests

A repository for learning and experiments.

## Local HTTPS setup

This server uses HTTPS and expects certificate files. Do not commit private keys.

Recommended local workflow:

1. Keep certs outside git, or rely on ignored files (`*.pem` is ignored).
2. Point each worktree to your local cert paths with environment variables.

If you need to generate local-only certs:

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 365 \
	-keyout key.pem -out cert.pem -subj "/CN=localhost"
python server.py
```

## Animation studio

A prompt-driven Manim pipeline: you describe a scene, the backend generates
Manim source, statically checks it, renders it, and serves the resulting MP4.

### Architecture

A modular monolith, laid out by dependency direction rather than by file type.
Imports run inward only — `api` → `application` → `domain` — and `domain`
imports nothing but the standard library.

```
backend/app/
  api/            HTTP surface: routes, DTOs, middleware, error mapping
  application/    Use cases: the render pipeline and the animation service
  domain/         Entities and the port (interface) definitions
  infrastructure/ Adapters that implement the ports
  core/           Settings, request context, and the composition root
```

Every external dependency sits behind a port in `domain/ports/`:

| Port | Local implementation | Swap target |
| --- | --- | --- |
| `SceneCodeGenerator` | any OpenAI-compatible chat API | hosted model, Anthropic |
| `SceneCodeValidator` | AST allowlist | — |
| `SceneRenderer` | Manim CLI in a subprocess | render farm |
| `ArtifactStorage` | local directory | S3 / GCS |
| `RenderJobRepository` | SQLite | Postgres |
| `JobQueue` | inline (synchronous) | Celery / arq / SQS |
| `Logger` | stdlib `logging`, JSON lines | Datadog / OTel |

`core/container.py` is the only module allowed to name a concrete adapter, so
replacing one is a change there plus a new file under `infrastructure/`.

### Choosing an LLM

Manim code is generated by a real model. Nearly every provider exposes OpenAI's
`POST /v1/chat/completions` shape, so one adapter
(`infrastructure/ai/llm_generator.py`) covers all of them and switching is two
environment variables — see `.env.example`.

| Provider | Cost | `ANIM_LLM_BASE_URL` |
| --- | --- | --- |
| **Ollama** (default) | Free, offline, no key | `http://127.0.0.1:11434/v1` |
| Groq | Free tier | `https://api.groq.com/openai/v1` |
| Google AI Studio | Free tier | `https://generativelanguage.googleapis.com/v1beta/openai` |
| Cerebras | Free tier | `https://api.cerebras.ai/v1` |
| OpenRouter | Has `:free` models | `https://openrouter.ai/api/v1` |
| OpenAI | Paid | `https://api.openai.com/v1` |
| DeepSeek | Paid, cheap | `https://api.deepseek.com` |

The default is a local Ollama, so nothing leaves the machine and no credential
is needed:

```bash
brew install ollama && ollama pull qwen2.5-coder
```

Point `ANIM_LLM_BASE_URL` at a remote host without setting `ANIM_LLM_API_KEY`
and the app refuses to start, rather than failing as a 401 mid-render.

**No agent framework.** LangChain and friends would add a large dependency tree
and become a second abstraction competing with the `SceneCodeGenerator` port.
The port is the seam; talking to a chat API is one HTTP POST.

Anthropic's Messages API has a different wire format, so it would be a second
adapter behind the same port rather than a flag on this one.

`ANIM_AI_PROVIDER=template` selects an offline keyword-template provider
instead. It needs no model and is what the test suite runs against.

### Render jobs

`POST /api/v1/animations` answers **202** with a job, and clients poll
`GET /api/v1/animations/{id}`. The inline queue finishes the work before the
response is written, but nothing in the contract says so — moving to background
workers is a change of `ANIM_JOBS_BACKEND` and needs no edit to the API or the
frontend. Statuses: `pending → generating → validating → rendering → storing →
succeeded | failed`.

### Executing generated code

Generated source is **never trusted** — all the more so now that a model
writes it and a prompt can try to steer what it writes. Two independent layers
stand in front of `subprocess.run`:

1. **Static validation** (`infrastructure/validation/ast_validator.py`) parses
   the source and rejects anything outside a narrow allowlist: imports beyond
   `manim`/`numpy`/`math`, `eval`/`exec`/`open`, private and dunder attribute
   access, filesystem attributes, executable module-level statements, `while`
   loops, and any class that is not the expected single `Scene` subclass.
   Nothing is imported or compiled to do this.
2. **Process isolation** — rendering runs in a child process with a scrubbed
   environment, a private working directory, a hard timeout, and no shell.

The system prompt restates these rules so the model aims at the right target,
but it is a hint and never a substitute: the validator rejects whatever comes
back regardless. When it does, its complaints are fed back to the model and the
generation is retried, up to `ANIM_AI_MAX_ATTEMPTS`.

This is not a sandbox. It raises the cost of a malicious or prompt-injected
generation sharply, but running genuinely untrusted prompts in production needs
OS-level isolation (separate user, container, seccomp) around the renderer too.
The API binds to loopback for the same reason.

### Logging

Call sites emit an event name plus structured fields — never a preformatted
string — through the `Logger` port. The stdlib adapter renders them as one JSON
object per line, which is the shape log shippers expect. Requests carry an
`X-Request-ID` that is bound to the ambient context, so every downstream record
(AI generation, validation, render, storage) correlates back to the request
that caused it. Routing to Datadog later means registering another factory in
`infrastructure/logging/factory.py`; no call site changes.

### One-time setup

```bash
# System dependencies (macOS / Homebrew)
brew install py3cairo ffmpeg pango pkg-config

# Python environment
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt

# Frontend
cd web && npm install
```

### Run it

```bash
ollama serve &        # or point ANIM_LLM_BASE_URL at a hosted provider
./run_api.sh          # FastAPI on http://127.0.0.1:8000 (docs at /docs)
cd web && npm run dev # Vue on http://localhost:5100, proxies /api/v1
```

Open <http://localhost:5100/animations> and describe a scene. The card shows
which provider and model produced each animation, and "View generated code"
shows the exact source that was rendered.

### Tests

```bash
cd backend && ../.venv/bin/python -m pytest
```

The suite runs without Manim and without a model: the AI provider and renderer
are replaced by fakes (`httpx.MockTransport` stands in for the chat endpoint),
while SQLite and local storage are exercised for real.

### Configuration

All settings are environment variables prefixed `ANIM_`, read once at startup
(`core/config.py`). Start from `.env.example`. The useful ones:

| Variable | Default | Purpose |
| --- | --- | --- |
| `ANIM_AI_PROVIDER` | `llm` | `llm` or `template` (offline) |
| `ANIM_LLM_BASE_URL` | `127.0.0.1:11434/v1` | Any OpenAI-compatible endpoint |
| `ANIM_LLM_MODEL` | `qwen2.5-coder` | Model name at that endpoint |
| `ANIM_LLM_API_KEY` | — | Falls back to `OPENAI_API_KEY` |
| `ANIM_AI_MAX_ATTEMPTS` | `3` | Generations per job, incl. repairs |
| `ANIM_OUTPUT_DIR` | `animations/output` | Root for the DB, library, scratch |
| `ANIM_JOBS_BACKEND` | `inline` | How render jobs are executed |
| `ANIM_RENDER_TIMEOUT_SECONDS` | `180` | Hard limit on a single render |
| `ANIM_LOG_FORMAT` | `json` | `json` or `text` |
| `ANIM_CORS_ALLOW_ORIGINS` | localhost:5100 | Comma-separated allowlist |

The API key is held in a `repr=False` field, so a settings dump cannot leak it
into a log line.

Everything under `animations/output/` — the SQLite database, the rendered
library, and scratch space — is a regenerable artifact and is git-ignored.

### Rendering a scene by hand

The versioned example scenes in `animations/scenes/` are still renderable
directly, independent of the API:

```bash
source .venv/bin/activate
manim -qh animations/scenes/example.py SquareToCircle --media_dir animations/output
```
